# DECISIONS — なぜこうなったかの記録

後から「なんでこうしたんだっけ」となったときに読む。新しい決定は上に足す。

## 2026-08 地を白に反転、青の流れを固定背景に

理由: 本人の要望。「背景色白のほうがいい、白と青って感じ」。
mofu-dev.com の白地に青の印象へさらに寄せる。

- 配色を反転: 地は白、文字は黒（#10151d）、差し色は青（#1d4ed8）。
  トークン名も cyan → accent に改名
- 青い流れの canvas を position: fixed の**固定背景**にした。
  スクロールしても絵は画面に残り、文字だけが上を流れる
- ポインタ視差は撤去（「カーソルに連動して動く機能はいらない」）
- 固定背景は黒い文字がどこを通るか分からないので、青の濃さに上限
  （#6ea6dc 相当 = 黒文字で 7:1）を設けた。強い青は右上だけ
- コードブロックは shiki の github-light をそのまま活かす配色に
  （ダーク用の上書きと明度フィルタを撤去）
- スライドのサンプル作品画は暗い絵のまま。白い誌面に絵が締まって
  見えるのでこれは変えない

## 2026-08 水槽を退役し、原点の mofu-dev.com 型へ（6度目の転換）

理由: 本人の要望。制作開始時に参照していた mofu-dev.com の
「シンプルかつ奥行き」に立ち返る。主役は背景の演出ではなく作品そのもの。

- トップに作品のスライドショー（three.js）。一枚絵が 6 秒ごとに
  にじむ遷移で次の作品へ移り、押すとその詳細ページへ飛ぶ
- 公開直後の見直しで並びを修正。最上段は名前・肩書き・自己紹介の
  ヘッダー（h1 はここ）にし、スライドショーはその直下に置く。
  最上段が作品の絵だけだと「何のサイトか」が先に伝わらないため
- 文字だけのヘッダーは「かっこよさが消えた」ので、シアンの光の
  背景画を敷いた。文字の載る左と下は絵の側で黒に落とす
- さらに「mofu-dev.com みたいに動かして」で、背景画を静止画から
  three.js のシェーダー（ドメインワープ fbm の流れ + 粒の明滅 +
  ポインタ視差）に置き換えた。静止画は WebGL 不可時の代替として残す
- スライドの抽象画だけでは作品の紹介と伝わらなかったので、絵の中に
  作品名・SAMPLE の印・アプリ画面のモックアップを描き込み、
  サンプル作品画として読めるようにした
- 作品の実画像はまだ無いので、slug から決まる配色の抽象画を
  プレースホルダーとして生成する。frontmatter の `cover` にパスを書けば
  実画像へ差し替わる設計にした（差し替え時にコードを触らない）
- キャプションは絵の上ではなく下の黒地に置く。絵の上の文字は
  コントラストを実測で保証できないため
- 全ページ背景だった水槽のコード一式（`src/components/webgl/`）は撤去。
  git 履歴にあるので戻したくなったら復元できる
- 自己紹介は「普段の業務ではモバイルアプリをつくっている」ことを
  先頭で明示する書き方に改めた（Web は個人の制作から、という位置づけ）

## 2026-08 背景を水草水槽（ネイチャーアクアリウム）に（5度目の転換）

理由: 本人の要望。webdesignclip.com の 3D/WebGL 系サイトのような装いに
戻したい。ただし今回は深海ではなく、熱帯魚・水草の
「見ていて落ち着く自然」がテーマ。

- 全ページ背景に three.js の水槽。奥から、水（光条 + カースティクス）→
  奥の水草 → 魚 → 手前の水草 → 気泡
- 魚は海時代の Boids + コード生成 3D メッシュ（git 履歴の BoidsFlock）を
  作り替えて復活させた。体高・ヒレ・縞・鼻先の色・泳層・速さをパラメータ化し、
  同じ仕組みから 10 種（テトラ4種・バルブ・グラミー・エンゼル・コリドラス・
  ハチェット等）を生成。深度連動・ベール・モデル差し替えは持ち込まない
- 初稿は水も緑にしたが「水は青がいい」で、水=青 / 水草=緑 に落ち着いた。
  ヒーローの色面（一枚絵）も「スクロールで残るのが違和感」で撤去し、
  最初の1画面は水槽そのものを見せる。plate トークンはこれで廃止
- 作りかけだった全面流体シミュレーションは置き換えて撤去。水の「らしさ」は
  光条・カースティクス・水草の揺れ・気泡で出す方が水槽らしく、計算も軽い
- 表の項目名を 名称/役割 → 作品名/担当 に、数えを 点/本 → 件 に直した
- fg-faint は #9d9b90 → #a8a69b。水の明るさの上に載っても小ラベルが
  4.5:1 を割らないための持ち上げ
- 文字組み・表・記事のミニマルな作法は tndhjm 型のまま維持。
  「装飾は背景の1枚だけ、情報は飾らない」が今回の折衷

## 2026-07 海を撤去し、tndhjm.com 型のミニマルへ（4度目の転換）

理由: 作品より演出が主役になっていた。「エンジニアっぽくない」という
本人の評価は正しく、流体・魚・深度は見事だが、見せたいのは作品と記録のはず。

- three / gsap / lenis を依存から外した。JS チャンク合計は実測で 1.56MB → 684KB
- 海の配色（深海の青〜シアン）だけを「ヒーローの色面1枚」として残した。
  色面の中の等深線と STATUS : WORKING の時計が、唯一の遊び
- 作品は Title/Client/Year/Role 型の定義リスト表（名称/年/役割/技術）に。
  罫線は行区切りの 1px だけ
- 日本語主体に戻した。英語は名前と固有名詞だけ
- 海のコード一式は git 履歴にある。戻したくなったら復元できる

## 2026-07 大物も 3D 化。シルエットは漆黒の帯の2種だけに

小魚に続いてサメ・クジラ・マンタ・クラゲも本人の要望で 3D にした。
断面リングの積層（サメ・クジラ）、キャンバー付き一枚翼（マンタ）、
半球 + 垂れ帯（クラゲ）をコードで生成。動きは種で違う——サメは横うねり、
クジラは水平の尾びれが縦に打ち、マンタは羽ばたきが翼端へ波及、
クラゲは傘が脈動して触手が遅れて揺れる。
大王イカとチョウチンアンコウは漆黒の帯に住み輪郭しか見えないため、
シルエット + 発光のまま残した（あの暗さでは 3D にしても違いが出ない）。

あわせて、スクロール中に生き物が上下へ跳ねる問題を直した。原因は
スクロール速度を位置に直接足していたこと。速度は捨て、なめらかに
補間される「深度」に結びつけた——潜れば帯の中心を過ぎた分だけ
静かに上へ流れていく（すれ違い）。ベールも CSS transition をやめ、
自前の指数追従にした（スマホの慣性スクロールで暗さが波打っていた）。

## 2026-07 近景の小魚だけ 3D 化。遠景はシルエット継続

当初 3D は「中途半端だと安く見える」ため見送ったが、本人の要望で再検討。
外部モデルを使わず、コード生成の 3D メッシュ（紡錘形の胴 + 尾びれ + 背びれ、
カウンターシェーディング + リムライト）で群れの小魚だけを 3D にした。
回頭は縦軸回転なので正面・背面の見付きが本当に変わり、旋回でバンクする。
クジラなどの大物は霞の中の影 = シルエットのまま。遠景が平板なのは
物理的にも正しく、大物まで 3D にする莫大な作り込みを避けられる。
同時に気泡を廃止（水槽っぽく見えるため）。マリンスノーは残した。

## 2026-07 渦の軌道は閉じさせる

攪拌点の角速度が無理数比だと軌道が閉じず、渦が形を崩して流れ去って見える。
全攪拌点の速さを基本角速度（周期 90 秒）の整数倍にし、軌道内の倍率も
整数（2, 3）にして同じ周回を繰り返すようにした。濃度も注入と減衰を
釣り合わせ（dissipation 0.3）、模様が飽和して潰れないようにした。

## 2026-07 泳ぎはシルエット + うねり + Boids。3D モデルは見送り

魚を「本当に泳いでいる」ようにする方法を検討した結果:

- 採用: UV 歪みの進行波（尾ほど振れる）+ Boids（分離・整列・結合 + 回遊目標 +
  カーソル逃避）。シルエットの美学のまま、泳ぎの説得力だけを上げられる
- 見送り: GLTF による 3D モデル化。**中途半端な 3D はシルエットより安く見える。**
  モデリング・ライティング・テクスチャ全部が高水準でないと成立せず、
  モデル調達（ライセンス）の問題もある。やるなら覚悟が要る

## 2026-07 ホスティングは GitHub Pages（無料枠は問題にならない）

- 公開リポジトリは Actions 分数無制限。push で無料枠は消費しない
- サイト 8.6MB（上限 1GB）、転送 100GB/月で個人サイトには余裕
- 代償として静的書き出し限定になり、次の制約を受け入れた:
  画像最適化なし / OG 画像はファイル規約でなく `npm run og` で実ファイル生成 /
  `/feed.xml` へのリンクは `<a>`（`<Link>` は RSC 先読みが 404 になる）

## 2026-07 可読性は実測主義。小ラベルだけ基準を緩める

- 「読める気がする」を禁止し、描画画素からコントラスト比を実測する方式にした
  （CSS の色文字列は Tailwind v4 の color-mix(oklab) が原因で解析できない）
- 本文 7:1 / 大きい文字 4.5:1。**11px の小ラベルのみ 4.5〜7:1 を許容**
  — 7:1 まで上げると本文と同じ明度になり階層が消えるため。意図的な妥協
- 本文の背後はベール（黒い膜）で水を落とす。演出を消すのではなく、
  読む場所だけ静かにする
